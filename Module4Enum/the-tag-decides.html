the tag decides

An enum is one value wearing one of several shapes. A hidden tag records which shape is in the slot right now. Everything else — how it’s matched, what it costs in memory, the two types that hold the whole language together — falls out of that one fact.

Pick any value in a program and it usually has one fixed layout: an i32 is always four bytes of integer. An enum loosens that. The value is allowed to be one of a few named alternatives, and it carries a small marker — the tag, or discriminant — saying which alternative is live. Read the tag and you know what’s in the slot. Six things follow. Each one below is a control you can turn, not a picture.

one value · several shapes

The shape–shifter

Here is one enum with five alternatives. Some carry nothing, some carry one piece of data, some carry several named pieces. Choose which alternative the value is. Only one can be live at a time — that is the whole point of the word or.

The alternative you picked is the tag. The bright box is the tag; the coloured boxes are whatever that alternative carries. Switch alternatives and the carried shape changes underneath the same variable.


  


  
  

    
the slot fits the largest tenant

    
The hidden tag, and the biggest tenant

    
The value has to fit in memory whatever shape it takes. So the compiler reserves a slot big enough for the largest alternative, plus room to record which alternative is in it. Change the live alternative below. The lit bytes — the part actually in use — shrink and grow. The slot does not.


    

      

      

      

      

        
in use now:  bytes

        
size_of::<Cell>() = 24 bytes — fixed

      

      
Rent a slot big enough for the largest possible occupant and it fits no matter who moves in. Flag(true) uses one byte and leaves the rest reserved; Span fills the payload. The size never moves, because the variable has to be able to become any alternative later.

    


    
compiled · x86-64 · rustc 1.75
      std::mem::size_of::<Cell>() returns 24: a 16-byte payload sized to the largest alternative (Span = two i64) plus an 8-byte region carrying the one-byte tag and its alignment padding.


    
simplified
      Default repr(Rust) does not promise where the tag sits or that the layout matches the boxes above — only that the slot can hold any alternative and record which one. Exact offsets are the compiler’s to choose and can differ by version and platform. Run size_of for the true number on a given machine.

  


  
  

    
match reads the tag

    
The switchboard

    
To use the value you have to ask which alternative it is. match does that: it reads the tag and routes down exactly one arm. Pick the live alternative and watch the matching arm fire. Then add an alternative to the enum — the compiler refuses to build until the match handles it too. You cannot forget a case, because forgetting is a compile error.

the two that run the language

    
Absence and failure are just enums

    
The same construct, twice, holds up most of Rust. A value that might be missing, and a result that might have failed, are not special syntax — they are this exact thing: a tag, and a payload behind it.


    
enum Option<T> { None,        Some(T) }   // maybe a value
enum Result<T,E> { Ok(T),  Err(E) }   // worked, or didn't


    
A lookup that may find nothing returns Option. Flip the input below between a value that exists and one that doesn’t, then try to pull the value out with .unwrap() — a method on the enum that returns the payload when the tag is Some, and stops the program cold when it is None.


    

      

        

          

        

      

      

      

        
        
      

      

      
To reach the payload you must first confront the tag. That is the trade: the compiler hands you a value only after you have said what to do when there isn’t one. The .unwrap() scattered through quick examples is this method — it skips the confrontation and accepts a crash if the tag isn’t the happy one.

    


    
compiled · rustc 1.75
      Unwrapping the empty case panics with the exact message called `Option::unwrap()` on a `None` value. Option is the honest replacement for a null pointer; Result is the honest replacement for a returned error code — both make “it might not be there” a shape you are forced to open.

  


  
  

    
when the tag costs nothing

    
The tag can hide

    
A tag usually needs its own bytes — that is why Option<i32> is wider than a bare i32. But if the wrapped type already has a value it can never hold — a reference can never be null, a NonZeroU32 can never be zero — the compiler stores None as that forbidden pattern and spends no extra space at all. That spare pattern is called a niche. Switch the inner type and compare.


    

      

      

      

      
Same wrapper, opposite outcome. When the inner type spends every bit pattern on real values (i32), the tag needs its own room. When it leaves one pattern forbidden, None moves in rent-free and Option<T> is exactly the size of T.

    


    
measured · x86-64 · rustc 1.75
      Every number above came from size_of: Option<i32> is 8 vs 4, but Option<&i32>, Option<NonZeroU32>, Option<Box<i32>>, Option<String>, Option<bool> and Option<char> are each the same size as the type inside. This is the same niche trick the layout in panel 2 hinted at — the tag finding somewhere to live for free.

  


  
  

    
where it breaks

    
The shadow

    
Pattern matching binds names to the pieces it pulls out of a value. That is its strength, and the place a real bug hides. Below, a payment routine adds inserted money to a balance. Its PaymentPending arm pulls a field called amount out of the value — and that name lands on top of the function’s own parameter, also called amount. From that line on, amount means the field, not the money just inserted. Insert two coins and watch.

With the shadow in place the second coin is ignored and the stored field is added instead — the balance is wrong and the printed line is wrong, yet nothing fails to compile. Rename one of the two amounts and the same routine reads correctly. The mechanism is sound; the collision of names is the trap.

    


    
observed · rustc 1.75
      This reproduces a bug that compiles without a warning: insert 0.75 then 0.50 and the second print reads $0.75, with the balance landing at 1.50 instead of 1.25. The fix is a rename — nothing about the enum or the match was wrong.


    
judgment
      Treat a shared name between a pattern binding and an enclosing variable as a smell, not a convenience. The compiler permits it, so the cost of a wrong guess here is silent — which is exactly the kind of failure worth meeting on purpose once.

  


  

    
One construct — a tag and a payload — runs from a five-line enum to the way the language handles absence and failure. The byte layouts here are drawn to show the principle; real offsets, tag positions, and the exact size of any type are chosen by the compiler and vary by version and target. std::mem::size_of and a debugger give the true figures on any given machine. Sizes and messages on this page were taken from rustc 1.75 on x86-64.
