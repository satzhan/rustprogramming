LeetCode Hard · 10-minute talk

Presentation checklist

Each line has three levels — aim as high as you can. C1 and C2 are required. C3–C6 carry the points. F1–F9 are optional.

Required — clear both

Criterion 1 2 3
C1 · FLOOR Owns the problem
1States the problem without notes; traces one example by hand.
2Names the naive approach and where it gets slow or wrong.
3Shows the exact input that breaks the naive approach.
C2 · FLOOR Owns the solution
1Walks the code and says what each part does.
2Points to the one line doing the real work, and why it's needed.
3Explains why the other obvious fixes fail and this one holds.
↑ required · everything below is where points are earned ↓
C3 This solution vs. the others
1Names how it differs from another solution to the same problem.
2States when each one is the better choice.
3Names what each trades away — time, memory, or simplicity.
C4 Syntax
1Reads the code aloud without losing the thread.
2Explains a tricky line — a borrow, a type, an iterator.
3Says why the language forces that line, and what breaks without it.
C5 Visuals
1One slide shows the idea instead of describing it.
2A diagram traces one real input from start to finish.
3The diagram singles out the step that matters most.
C6 Rehearsed
1Said aloud at least once; timing known.
2First line and last line are fixed.
3A backup is ready if the live demo fails.

Optional · F1–F9  — reach for these after the rest holds

Criterion 1 2 3
F1 Structure
1Has a beginning, middle, and end.
2The order is clear; each part says what it covers.
3At any point, where the talk is, is obvious.
F2 Delivery
1Audible; not read word-for-word off the slide.
2Steady pace; eyes on the room, not only the screen.
3Volume and pace shift to mark what matters.
F3 Time
1Ends near the limit.
2Lands inside the limit without rushing the end.
3Paced evenly; no part starved to rescue another.
F4 Questions
1Answers a direct question about the solution.
2Answers a question that wasn't prepared for.
3Admits the limit honestly, and says how to find the answer.
F5 Takeaway
1Ends with a clear summary line.
2Leaves one specific thing worth remembering.
3That one thing is the point of the talk, not a side note.
F6 Complexity & trade-offs
1States time and space cost.
2Justifies the cost from the code, not from memory.
3Compares against the naive cost and says what the gap buys.
F7 Code on screen
1Shows only the key lines, not the whole file.
2The shown lines are readable; the important part stands out.
3The screen points to the line that carries the idea.
F8 Clarity
1The one or two technical terms are defined.
2Defined in plain words, not more jargon.
3A short example makes the term concrete.
F9 · BONUS The room follows
1Most can restate the rough idea afterward.
2Most can say why the naive approach fails.
3Most could sketch the solution's shape from memory.
