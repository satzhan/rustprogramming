What the trace shows

  1. A clone adds to a tally; a move copies bytes and touches no tally. Rc::clone wrote one number in the leaf's block. Moving top into the heap copied all 24 bytes, two keys included, and neither tally moved.
  2. A look is just an address, and sometimes it points into the heap. The first call's node is the address of root's stack slot. Every call after that gets the address of a hook inside the parent's block.
  3. rc and node hold the same number. The Rc inside Some takes up the whole Option, and None is eight zero bytes.
  4. Every door on the path carries a tick. While the walk is at the leaf, node 4's sign says 1 as well.
  5. A new frame lands on an old one's bytes. Node 7's frame sits where the leaf's frame was, and still shows the leaf's numbers until each slot is written.
  6. Temporaries are real. Each guard the written code never names still gets a 16-byte slot, and it dies at the semicolon. Two in one statement die in reverse order.
  7. A failed try_borrow_mut writes nothing. It reads the sign, sees a look, and hands back an Err without touching the sign.
  8. take moves a key out of a hook without touching the tally. The hook gets eight zero bytes; the leaf's tally stays at 2.
  9. Dropping a node frees what only it held, children first. Node 7 had a single key, on node 4's hook, so it was freed inside node 4's drop, before node 4's own block. The leaf had other keys and survived.
  10. A hidden weak count keeps each block alive to the very end. Every block's second counter reads 1, though no weak key exists: the strong keys share one. It drops to 0 only after the node inside is fully dropped, and only then is the block freed. factWe read each block at the instant it was freed: strong 0, weak 0, sign 0.
  11. Freed memory isn't wiped. The allocator writes its own bookkeeping over the first 16 bytes of each freed block. The rest stays, including a key to node 7 sitting in freed memory, pointing at another freed block.

factEach 48-byte block starts 64 bytes after the one before it. The 8 bytes just before each block hold the allocator's note about it, 0x41: 64 bytes, plus a flag in the lowest bit. modelThe allocator's bookkeeping in freed blocks is glibc's: a scrambled link to the next free block of the same size, then a check value. Another allocator would leave different bytes.

Both programs were compiled with stable Rust 1.97, edition 2024, in a debug build, and the explicit one was stepped line by line in gdb 15.1 on x86-64 Linux. Steps for two lines that touch no memory (the total line and the arm's closing brace in sum) are left out. The TreeNode struct and the use lines sit above the code shown, and aren't part of the trace.
